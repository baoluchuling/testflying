# Store provider capabilities

`store-provider` is a native Rust implementation. Both Connector transports call the same `Gateway`; it resolves the Apple app from the envelope Bundle ID and uses the envelope package name for Google. Payload `app`, app IDs, account IDs, platform overrides, and package overrides never select the target.

The following are actual in-process HTTP integration tests in `crates/store-provider/tests/live.rs`. See [verification.json](verification.json) for current test counts, exact source hashes and commands, and [verification.md](verification.md) for lifecycle and unverified-environment boundaries. These fixtures are not claims of live vendor acceptance.

Scope and limits:

- iOS version listing returns all paginated version states, latest marker and node-derived editability. Creation resolves the trusted app identity and creates a MANUAL IOS version without build attachment or review submission. `apple_versions_report_all_states_and_only_writes_stop_when_latest_locked` and `apple_create_version_is_manual_without_submission_and_validates_on_the_node` cover real fake-Apple HTTP, no real accounts.

- Apple `store_releases` returns version states and editability; Android PPO list returns an empty list. Android version creation, PPO creation and marketing page writes are explicitly rejected. There is no independent review submission, publishing, release rollout, or review reply operation; normal Google edit commits may send changes for review.
- Resource lists preserve the Go request limits except Apple screenshot reads, which follow up to 20 same-origin, same-path collection pages with a 10,000-object bound. Reviews expose continuation.
- CPP deep links and keywords are not writable fields in the Go CPP implementation and are not newly exposed. Existing CPP lookup verifies ownership before modifying a supplied page ID.
- Review filtering operates on the returned upstream page; it does not fetch hidden extra pages to fill a filtered result. Dates use the selected IANA zone; response boundaries are UTC equivalents.
- Images must satisfy generic safe image decoding bounds. Store-specific screenshot/device dimensions are still ultimately validated by the vendor; the provider does not claim that every safe image matches every Apple/Google slot.
- Google edit cleanup errors return `store_edit_cleanup_failed` because remote disposal cannot be guaranteed after an upstream outage. Connector keeps the vendor worker and account permit alive through caller timeout/disconnect and discards late results; abrupt process death can leave a remote edit to expire.
- Mutations are not retried or replayed. Apple multi-step writes and CPP/PPO creation are not transactional; a later failure can leave already-applied Apple changes. Mock output is development behavior and is not evidence of live protocol support.
- Omitted `syncScopes` preserves default text selection; explicit `[]`, null, unknown scopes and non-array values are rejected. Omitted `storeRelease` selects the highest numeric Google version; an explicit target must contain known, nonempty string selectors, and a supplied version name constrains matching releases.
- Omitted image slots stay unchanged. An explicit slot with `urls:[]` and/or `assets:[]` and no sources clears that slot; malformed/unknown slot objects cannot be interpreted as a clearing request. Writable slots are phone/tablet/foldable screenshots on Apple, and phone/tablet/feature graphic on Google; Google tablet writes affect both tablet image groups. Apple validates runtime image specifications and the processed specId before replacing selected placements, never deletes existing library assets, and waits up to 30 seconds per image. Failed staging can leave unplaced library assets. Failure during placement replacement can leave partial changes; there is no automatic mutation replay.
- No external credentials or store writes are used by the tests. Test keys are throwaway generated local keys, and all upstreams bind loopback within the test process.
