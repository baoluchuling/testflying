# Testflying Screenshot Connector for macOS

This ZIP contains the Apple Silicon (arm64) Rust worker and the credentials for one Screenshot Connector. Keep it private. Move the extracted directory to a permanent location under `~/Library/Application Support/` on the assigned Mac.

1. Set owner-only permissions with `chmod 700 . && chmod 600 connector.json`.
2. Install a Codex CLI that supports App Server Goals and dynamic tools, make sure `codex` is on the installation account's `PATH`, and sign in to Codex with that account.
3. The worker uses the account's existing Codex login and configuration. Each screenshot Goal explicitly uses the built-in `danger-full-access` mode with `never` approval, allowing Codex to manage projects and simulators outside the task's temporary directory under the installation account's OS permissions. The initial turn sets the matching `dangerFullAccess` policy, inherited by later Goal turns. No custom permission profile or global Codex configuration change is required. Set `codexPath` or `codexHome` in `connector.json` only to override a nonstandard installation or configuration path.
4. Prepare the local projects and simulators. Codex finds the project on this Mac using its local permissions. Android uses a local ADB server and an ADB binary from the optional `adbPath` or the Android SDK.
5. Run `sh ./install.sh` as the screenshot account. In a local interactive desktop terminal, the installer opens Finder at this installation's `screenshot-connector` and opens **System Settings → Privacy & Security → Full Disk Access**. Add that executable with **+** (use **Command+Shift+G** to enter the printed full path), enable access, then return to the terminal and press Return before approving the administrator prompt. Where macOS offers folder selection, you can grant the project folders you need. This confirmation is your acknowledgement, not an automatic permission check. The script starts a system LaunchDaemon that runs as the screenshot account, reconnects to the center after network interruption, and starts at macOS boot. Keep the extracted directory in place.
6. Open the admin page and refresh the screenshot node connection status. The installer also prints the exact `sudo launchctl print system/…` command for local status.

`sh ./run.sh` runs a single job manually. The background service receives task notifications over the encrypted WSS connection. Each job starts a native Codex Goal with the caller's original prompt. Codex reads the center-generated `jobId`, app identity and ordered `target` array through `get_capture_task`, finds the project, and prepares each requested screen. Capture and upload tools use the same zero-based `targetIndex`. The same jobId is returned to the caller and used by the node and future result notification. Retryable errors go back to the same Goal; every target must have a confirmed OSS upload before it completes. This worker uses task protocol 3; old workers, including protocol 2, cannot claim these new jobs. External result notification remains pending until its protocol is connected.

From node 0.2.4, the worker advertises timing protocol 1. The center calculates each job's execution budget at claim time: preparation minutes plus the number of ordered targets multiplied by per-image minutes. Defaults are preparation 30 and per-image 15 (a 5-minute baseline with threefold allowance), so one target has 45 minutes and 64 targets have 16 hours 30 minutes. Completing early ends immediately. Upload timing and retries do not renew the budget. The center retains a further six-minute delivery allowance. Settings changes affect subsequently claimed jobs; external callers send no timeout parameters. A center without timing support retains the legacy 24-minute worker limit. Both an upgraded center and screenshot worker are needed for dynamic budgets.

Timing-aware tasks report `codex_execution_timeout` for budget exhaustion and fixed Codex protocol stage codes for other failures. Center logs correlate `screenshot.claimed` budget metadata and terminal failures using the jobId as requestId. They never contain the prompt, token or signed upload URL. Uncertain upload results keep their existing delivery_unknown behavior.

To upgrade an existing node, copy the new `screenshot-connector`, `run.sh`, `install.sh` and `testflying-prod-ca.crt` into the original installation directory. Keep its `connector.json` and run `sh ./install.sh` to restart the service.

### File access and automatic restart (0.2.5)

macOS file privacy permissions are separate from Codex's full-access sandbox policy. Only you can approve them in System Settings. The installer never edits TCC, resets existing permissions, probes private folders, or asks for unrelated camera, microphone, contacts or location access. Grant access to the exact installed `screenshot-connector`, rather than a copy in Downloads or a general-purpose shell.

For an already installed service, run `sh ./install.sh --permissions` from the original installation directory in the screenshot account's local terminal. After completing the system authorization, press Return to request a graceful service restart. `launchd` relaunches it after exit because `KeepAlive` is enabled; `RunAtLoad` also starts it at boot. If macOS asks the running worker to quit while applying access, the installed service is likewise relaunched. You do not need to reboot the Mac. `sh ./install.sh --restart` requests only a service restart and can also be used after manually granting permissions. It refuses to install a missing service or replace a different installation.

Over SSH, or without an interactive terminal or that account's GUI session, installation prints manual instructions and preserves its existing unattended behavior. A standalone `--permissions` invocation only prints instructions in that case and does not restart the service. The background worker never opens System Settings. If you cancel the interactive guide or send end-of-input before confirming, it does not install or restart anything.

This release has no stable Developer ID signing identity. macOS may require renewed authorization after a program update. If the old switch is enabled but access is still refused, remove the old entry and add the current executable again, then restart the service. Automatic permission carryover across upgrades is not guaranteed. Manually running `run.sh` does not install `launchd` supervision and will not automatically relaunch when it exits.

Apple references: [file access settings](https://support.apple.com/en-lk/guide/mac-help/mchl211c911f/mac), [file system permissions and code identity](https://developer.apple.com/forums/thread/678819).

From the installation directory, run `tail -F connector.log` to follow the local service log. It records connection status, job IDs and complete prompts, Codex Goal diagnostics, and screenshot delivery status. Prompts are JSON strings so multiline tasks stay on a single log line. The file is private to the installation account. The Connector removes entries older than 24 hours on startup and every minute while the service is running. Native Goal history follows the installation account's Codex history.

The bundled CA is used for the center connection. For a different private CA, set `caFile` to its absolute path.
