# 商店截图图文内容审核

所有截图任务默认执行，适用于任意页面、设备和语言，无需提示词再次声明。审核对象是当前目标画面，不是整款 App 的功能、全部目录或法律合规调查。下列保守素材选择标准由项目方明确要求，部分严于商店通用规则；不能把每次素材淘汰都描述为平台已认定违规。

## 看完整画面，也读文字

逐张查看完整原图，检查所有可见图片和文字：置顶／推荐卡片、小封面、Banner、侧卡、背景、播放器缩略图，以及书名、副标题、简介、正文、榜单标签、按钮和弹窗。边缘仅露出一部分的内容也不能漏；必要时放大查看原图，不修改交付文件。不要只审核主图，不以“封面加载了”代替内容检查，不以 OCR 命中／未命中单独判通过。

阅读当前语言的实际语义并结合画面判断，不机械按单个词过滤。明显不合格就淘汰；看不清或含义不明时重新查看必要上下文，或换为可确认合适的真实内容，不能猜测后宣称通过，也不无限追查无关功能。

## 默认排除

| 类别 | 不用于本项目商店截图的可见内容 |

| 暴力 | 打斗、血腥伤口、残肢、虐待、自残、明显武器威胁或暴力威胁，以及对应的暴力描述／宣扬 |

## 其他商店展示检查

- 隐私：不能出现凭据、Token、真实个人联系方式、私人聊天、地址或订单等敏感信息；只用已有获准的演示账号／数据或非敏感真实界面，不为截图伪造正文或 UI。
- 宣传：排除误导性的应用商店排名、下载量、官方背书、奖章、用户证言和价格／限时优惠宣传。区分应用内内容排行与应用商店成绩：书籍排行或正常内容标签不因出现数字／“热门”就自动判为商店排名宣传；结合实际语义判断。
- 品牌与权利：留意第三方品牌、商标、人物肖像和素材授权风险，已知未获授权的不用；不能凭画面断言已取得版权。不为普通截图扩展成版权调查；必要缺口明确记录。iOS 截图避免无关的其他移动平台或替代商店标识，真实获准交互另按实际要求处理。
- 真实体验：必须是任务指定 App、设备、语言及线上正式环境的真实页面。加载失败、破图、占位、调试标记或非目标遮挡仍按主流程处理；不能用启动图、登录页、替代页面或合成画面冒充指定目标。只核对目标画面，不额外验证无关功能是否可用。

## 不合格后如何继续

记录 targetIndex（如有）、实际位置和具体问题，例如“左下封面男性敞衣露胸”或“置顶标题将霸凌包装为恋爱”，不只写笼统的“内容审核失败”。不要在日志或错误详情复制敏感文字／个人信息。

通过真实 UI 换选合适的书籍／内容、切换卡片，或在仍满足原页面要求的范围内调整滚动位置。不能删用户收藏、修改线上榜单／推荐源数据、替换封面文件、伪造数据，不能裁切、打码、改字、P 图来隐藏问题；也不能滚走或替换用户明确要求的目标来冒充完成。没有合适真实内容就保留缺口。

Connector 候选图使用实际 ID 和 targetIndex 撤销，再重拍并复查完整图文；上传、撤销、最终提交未知时先确认同一操作。沿用首轮最多两次完整尝试、整轮结束再回补的规则；局部内容不合格不直接结束整单，实际无法恢复或预算耗尽时按已有失败协议报告。已最终提交的历史任务不在此重拍范围。不增加外部字段或错误码。

## 平台依据与范围

以下为2026-11-26核对的官方资料，供理解平台规则；项目默认筛选以本页已明确的更保守标准执行，不要求每次截图联网重新查政策，也不保证商店必然通过审核。

- [Apple App Review Guidelines 2.3](https://developer.apple.com/app-store/review/guidelines/#accurate-metadata)：截图应反映真实使用；即使应用评级更高，公开截图仍应适合4+；注意素材权利、个人数据和其他平台标识。
- [Google Play Metadata](https://support.google.com/googleplay/android-developer/answer/9898842)：公开素材应适合普通受众，避免性暗示、不雅文字、血腥暴力等。
- [Google Play 商店页建议](https://support.google.com/googleplay/android-developer/answer/13393723?hl=en)：隐私、误导宣传、冒充及受限制内容。
- [Google Play 截图规范](https://support.google.com/googleplay/android-developer/answer/9866151?hl=en)：真实体验、排名／优惠宣传及设备展示等要求；某些条款属于推荐展示条件，不混同为所有截图的一般硬性禁令。
