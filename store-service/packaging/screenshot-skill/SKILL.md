# 移动应用截图

按用户实际范围冻结 **设备 × 语言 × 页面**，采集真实 App 的原始 PNG。四类设备为 `ios/iphone`、`ios/ipad`、`android/phone`、`android/tablet`；只执行用户选择的子集。此包提供共同工作流、iOS 配置 runner 和 Android 原始截图助手。导航由真实 UI 自动化工具完成；Android 助手不冒充自动导航器。

## Connector 任务

通过截图 Connector 执行时，先阅读 [Connector 交付与失败协议](references/connector-protocol.md)，再按下文准备、采集和审阅。以 `get_capture_task` 的目标数组逐项执行，不展开为笛卡尔积；交付、撤销和整单确认使用节点实际提供的工具。

## 执行顺序

1. **确定范围与来源。** 沿用会话确认的 App、版本/build、分支/SHA、环境、语言、页面与设备；未知项先查本机项目、安装包和已有记录，只有影响执行且无法查明时才询问。冻结完整矩阵并记录每格状态，不因页面失败缩小分母。旧稿只在用户允许且版本、语言、页面和视觉要求均匹配时复用。
2. **补齐环境。** 先查现有工具链、缓存、设备及实际入口。缺工具、SDK、运行时、依赖或连接时，主动查找、安装、配置并做最小可用性验证；工具不可用时尝试合适的真实 CLI 或原生 UI 替代。能继续的工作继续推进，不能第一次缺环境就结束。只有实际尝试后仍无法补齐，或缺少无法代取的账号、凭据、授权、硬件时才停下受影响范围，报告尝试、原始错误和所缺项。不要编造凭据、绕过平台授权或擅自启用付费服务。Apple 构建仍遵循环境现有构建授权能力；不因导出本 Skill 安装或升级系统环境。
3. **准备设备与应用。** 每次核对实际包身份和环境。用户要求重新安装时，从确认的包重新安装，保留安装收据；语言切换按要求先重启目标模拟器到指定系统语言，再打开 App，核对实际语言。不要仅改 App 进程参数就宣称系统语言已切换。Simulator 使用同源同版本 Simulator `.app`，不能把真机 IPA 当成 Simulator 包；Android 使用实际 APK。按设备串行操作，资源不足先处理任务自身的占用和可重建缓存，保护其他任务和唯一原始证据。
4. **导航与采集。** 通过当前真实 UI 确认入口、控件和页面状态；优先语义定位，手势控件不暴露可点击节点时，使用新鲜 AX/UI 树或当前原生截图中的真实 frame。进入页面后做一次就绪等待：目标页与真实列表、封面、正文或播放内容出现，拦截已知加载、错误和意外弹窗。**就绪后，每张正式截图前至少额外等待 2 秒；页面特殊要求更长时采用更长时间。补拍同样执行。** 等待不等于已加载成功。随后保存原始 PNG，标记 `collected`，继续其余目标；不在每次点击后做完整质量审核。
5. **集中检查与补拍。** 完成本轮全部可执行目标后，按 [检查与补拍](references/review-and-retake.md) 逐张查看原图，同时集中校验文件、尺寸、SHA 和包/设备绑定。封面、海报、侧卡与推荐图均检查加载结果。**空白、占位骨架、破图、加载失败或图文不对应必须判失败并重新截图。** 只补拍失败项，保留旧稿和记录；补拍后再检查被替换图片。确实无法加载时保留阻塞证据与缺口，不交付占位图冒充完成。
6. **交付。** 按设备/语言/页面保存原图，附数量、来源、SHA 和缺图原因。全部最终文件先校验，再复制到成品目录；不裁切、缩放、修封面或合成 UI。用户暂停时停止截图、构建及相关子任务，保存进度；导出或修改 Skill 不隐含恢复设备任务。

## 平台入口

- **iPhone / iPad：** 使用 iPhone 18 Pro Max + iOS 27、iPad Pro 13 英寸（M5）+ iPadOS 27，均为竖屏；先按 [iOS 工具与设备准备](references/ios.md) 绑定指定机型、27 系列 runtime 与实际 UDID，不能沿用旧设备/旧系统。有稳定页面配置时使用 [iOS runner](references/runner.md) 和 `scripts/screenshots.py`；原生 UI 动态路径使用实际工具采集，保留同等来源与原图检查记录，不为套 runner 改变页面。
- **安卓手机 / 平板：** 先按 [指定 Android 模拟器](references/android-devices.md) 选择或创建 Pixel 10 Pro XL / Pixel Tablet 的 Android 17 QPR2（API 37.2）专用 AVD，两者均采集竖屏。核对机型、AVD 名称、系统镜像、分辨率、density 和方向；未通过不得沿用旧设备。再按 [Android 流程与助手](references/android.md)，通过明确 serial 的 ADB 和实际原生 UI 导航；`scripts/android_screenshots.py` 负责原始采集与批末文件校验，不启动 AVD、不安装、不导航，也不判断封面视觉加载状态。
- **App 特定行为：** 用户明确指向对应产品时再读 [产品适配](references/app-adapters.md)；Amberia 原有语言和保护配置见 [Amberia 参考](references/amberia.md)。当前会话要求优先于历史示例，不复用历史 UDID、安装路径、版本或接口故障结论。
- **设备尺寸：** 四类设备的原图规格及方向见 [设备尺寸](references/device-sizes.md)；安卓手机为 1344 × 2992（竖屏），安卓平板为 1600 × 2560（竖屏），iOS 规格沿用表中配置。这里约束原始 UI 素材，不要求与最终商店合成图画布相同。采集前核对实际原生尺寸，不缩放凑规格。
- **覆盖与目录：** [矩阵和记录](references/matrix.md)。iOS runner 的 manifest 与 Android sidecar 是各平台证据；最终仍须对照同一份完整矩阵合并统计。

## 内容与环境真实性

- UI、正文、书籍或剧目采用当前语言的真实内容，不自行翻译内容、改封面或用 Mock 填充。封面标题为英文是否可接受沿用用户明确约定；不得据封面标题推定正文语言。
- 沿用用户对封面的标准，检查所有可见位置，包括侧卡、Banner、收藏书和排行。要求排除裸胸腹、内衣或色情时，通过真实 UI 换选合适内容；不能擅自修改线上榜单或源数据。截图专用安全书单只有用户明确允许时使用，并披露差异。
- 对播放页选择清晰、稳定且符合内容要求的真实帧，排除黑屏、模糊过渡、加载层和不应保留的操作遮罩。不能拿详情页、封面大图或另一个分段静默替代；允许使用其他分段时记录真实分段。
- 正式环境需核对实际 API host；嵌入 H5 还需核对服务端配置及实际加载域名，区分配置证据与实际运行证据。日志只保留必要的公开状态、host/path、错误或 requestId，不复制 token、Cookie、完整请求头或账号凭据。
- OCR 为辅助能力，不能代替原图审阅或证明封面已加载。未配置 OCR 就不宣称通过 OCR；明确配置了 OCR 断言时保留实际结果，工具失败不得虚报通过。
