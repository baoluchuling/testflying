# testflying UI 基线

本文档冻结当前已通过验收的 UI 和交互，后续数据接入、接口替换和功能实现不得破坏这些行为。

## 产品定位

`testflying` 是内部 iOS 测试分发工具，不面向普通终端用户。主要使用者是移动端测试、研发和测试管理员，用来查看内部应用、安装构建、管理设备、跟踪账号续费和接收构建通知。

## 页面结构

底部导航固定为四个入口：

- 首页：设备与账号续费提醒、应用总览、应用列表、下载/安装操作。
- 设备：当前设备、设备池、证书与权限入口。
- 通知：通知类型筛选、今天/昨天通知列表。
- 我的：个人身份、工作台、偏好设置。

应用不再作为独立 tab，应用总览和应用列表合并在首页展示。

## 首页基线

- 顶部标题为可折叠标题：展开时大标题左对齐；上滑时大标题渐隐；小标题在大标题 50% 透明度后从下沿往上翻出并逐步显示。
- 首页只保留一个“设备与证书”快捷入口，点击后切换到设备页。
- 账号续费提醒跟随首页设备卡展示，不做全局横幅。
- 应用总览支持展开卡片模式和收起横向 tab 模式。
- 应用总览点击非“全部应用”项时筛选列表，不主动滚动定位；再次点击同一项恢复全部应用。
- “全部应用”在展开模式不展示选中态，在 tab 模式展示选中态。
- 应用列表默认按添加时间排序，支持通过底部“调整排序”入口打开 sheet 手动排序。
- 主列表不展示拖动手柄；排序 sheet 只展示应用图标、名称和右侧拖动标识。
- 下载进度直接体现在下载按钮上，圆环 100% 表示完整进度。

## 设备页基线

- 顶部标题使用与首页一致的可折叠标题动效。
- 当前设备卡展示设备名称、UDID、系统版本、证书状态和最近安装。
- 设备池展示设备名称、负责人、状态和环境详情。
- 证书与权限保留企业签名和调试权限入口。

## 通知页基线

- 顶部 tab 固定在标题栏下方。
- 上滑时大标题渐隐，小标题从下沿往上翻出。
- 顶部四个通知类型在一排展示：全部、构建、账号、设备。
- 点击通知类型筛选列表内容。
- “全部已读”保留在顶部操作区。

## 我的页基线

- 顶部标题使用与首页一致的可折叠标题动效。
- 保留测试管理员身份、工作台入口和偏好设置。
- 偏好设置当前为本地交互反馈，不连接真实账号系统。

## 数据和功能边界

- 新应用由包上传或后端同步后自动进入应用列表，设备端不负责手动新增应用。
- 当前阶段使用本地 mock service 提供数据，不发起网络请求。
- mock service 必须覆盖应用、构建、设备、开发者账号续费、通知、安装任务和手动排序。
- 真实接口接入前，UI 验收以本文档和 widget test 为准。
